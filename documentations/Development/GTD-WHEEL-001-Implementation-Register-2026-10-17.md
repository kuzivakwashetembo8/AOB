**Asset facts:** Toyota, Defender and Dodge each contain ONE original
GLB mesh with no independent wheel nodes. Their decoded geometries hold
approximately 1452, 2633 and 3640 connected islands respectively.
Offline source island analysis produced four per-corner source-backed
tire/rim pivot assemblies with unchanged source triangles and materials.
The wheel derivation runs during preview BUILD, not each game startup.
A failed future extraction copies the untouched original and does not
pass the rig-admission gate.

**Code implemented:** `src/game/vehicles/mvrs-wheel-admission-001.ts` gates
chassis-driving admission; `ambient-fleet-driving-011.ts` identifies native
MVRS pivots; `mercer-additional-parked-glbs-006.ts` selects generated
derivatives only in production-mode bundle for this review branch;
`scripts/wheel001_asset_audit.mjs` and
`scripts/wheel001_extract_wheels.mjs` process exact source assets before
TypeScript validation and packaging. The GLB binaries are build artifacts,
not replacement commits to original owner models.

**Unresolved acceptance gates:**

  wheels rotate forward/reverse, steer visibly on the correct front axle,
  remain intact, have correct rim and hub centers, and contact pavement.
  In particular +Z inferred front/rear axle labels must be confirmed
  against each actual vehicle's nose.
- The Dodge derivative is ~5x its Draco-compressed source. Its load and
  first-frame performance must be measured against 60,000ms SLO.
- No signed-off MVRS-1 qualification manifests, server registry promotion

  *structurally rigged* models for owner's visual review; the production
  admission contract must require fully approved asset hashes.
- Vercel output and unit tests do not themselves establish four-car wheel
  animation acceptance on user device.
- The optional GitHub Action Blender probe failed before steps began;
  actual Node/glTF-Transform build audit succeeded instead.
